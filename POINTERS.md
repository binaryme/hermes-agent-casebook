# Pointers

Documented Hermes Agent behaviors that still surprise operators. Each line links to the upstream source or docs at v0.23.1 (commit `3b421578`). These are not entries: upstream already describes them, so there is nothing to reproduce, only something to read before you are surprised.

- **E8. A `GH_TOKEN` or `GITHUB_TOKEN` in the environment never reaches the agent's subprocesses.** Both are in the list of variables stripped from every spawned subprocess ([local_env_policy.py L413-L418](https://github.com/NousResearch/hermes-agent/blob/3b421578588243f920886e6fe79a6faa87ea026e/tools/environments/local_env_policy.py#L413-L418)), so `gh` run by the agent is not logged in even when `gh auth status` works in a shell. Sign `gh` in through its config directory for each profile, and see `terminal.home_mode` for where that directory lives ([configuration.md L344-L364](https://github.com/NousResearch/hermes-agent/blob/3b421578588243f920886e6fe79a6faa87ea026e/website/docs/user-guide/configuration.md?plain=1#L344-L364); for kanban workers, [kanban.md L68-L79](https://github.com/NousResearch/hermes-agent/blob/3b421578588243f920886e6fe79a6faa87ea026e/website/docs/user-guide/features/kanban.md?plain=1#L68-L79)).
- **E10. The kanban dispatcher runs inside the gateway and starts agents on its own.** It ticks every 60 seconds by default, picks up ready tasks, and with `review_dispatch: true`, also the default, spawns the assigned profile as a reviewer for tasks in review. Set `review_dispatch: false` for boards that only humans review ([kanban.md L314-L335](https://github.com/NousResearch/hermes-agent/blob/3b421578588243f920886e6fe79a6faa87ea026e/website/docs/user-guide/features/kanban.md?plain=1#L314-L335)).
- **E12. `HERMES_WRITE_SAFE_ROOT` guards `write_file` and `patch`, not the terminal tool.** The official image sets it to `/opt/data`, and a blocked write returns `Write denied: ... is outside HERMES_WRITE_SAFE_ROOT` to the agent. The model may still claim the edit succeeded; trust the file-mutation verifier footer over its summary ([security.md L396](https://github.com/NousResearch/hermes-agent/blob/3b421578588243f920886e6fe79a6faa87ea026e/website/docs/user-guide/security.md?plain=1#L396) and [L426-L430](https://github.com/NousResearch/hermes-agent/blob/3b421578588243f920886e6fe79a6faa87ea026e/website/docs/user-guide/security.md?plain=1#L426-L430)).
- **E13. Mattermost is configured through environment variables first.** The manual setup puts `MATTERMOST_URL`, `MATTERMOST_TOKEN`, `MATTERMOST_ALLOWED_USERS` and the optional behavior settings in `~/.hermes/.env`; only some settings have a `config.yaml` spelling. Look in the environment, not in `config.yaml`, when you check how a running gateway is set up ([mattermost.md L141-L174](https://github.com/NousResearch/hermes-agent/blob/3b421578588243f920886e6fe79a6faa87ea026e/website/docs/user-guide/messaging/mattermost.md?plain=1#L141-L174)).
